# 产品 UI 设计与验收

## 确定范围与设计依据

- 查阅适用的项目约定、产品需求、任务记录、UI 规范与现有实现。识别目标用户、使用频率、正常入口、主要操作、内容密度及适用状态。新功能先核对已确认的业务规则和验收条件，局部迭代按影响范围检查。
- 首次设计、整体验证或视觉重做时，说明主要任务和品牌气质如何影响信息层级、排版、配色、素材及反馈。把参考作品的具体长处转为适合当前产品的判断依据，如扫读效率、阅读节奏、控件一致性或图文比例。将项目主题、参考画面、数值和资产记录在项目资料里。
- 从核心任务选择代表界面。辅助入口只验证自己的用途。若方向要覆盖不同密度或任务类型，加入有代表性的对照界面，用同一套真实感内容验证这套设计是否适用于扫读、阅读、输入或浏览。未来业务尚未确定时，可用模拟内容试排布局，并写明验证边界。
- 记录视觉确认适用于哪些页面、任务和视口。后续功能复用在相应场景验证过的规则。遇到新的页面类型、密度显著变化、品牌表达断裂或整体风格被否定时，重新验证受影响的通用设计。方向明确时集中打磨一个方案，有实质取舍时再比较少量候选。

## 设计与打磨

- 根据用户需要辨认、比较或操作的内容组织首屏。列表以可扫读的列宽、行距和对齐为主。长正文控制阅读行宽。多字段表单按填写顺序分组。关联页面统一工作区边线，正文和表单可有各自宽度。窄屏按阅读和操作次序重排，检验长内容、切换断点和关键操作可达性。
- 用真实语言、数字和内容试排标题、正文、辅助文字和数据。调节字号、字重、行高和留白以建立层级。检查跨语言字形、字体回退、长文换行、截断后的完整值，以及适用的数字对齐。
- 按用途定义颜色和控件规则，覆盖背景、内容表面、文本、边界、主操作、选中、业务状态、反馈和危险操作。优先复用经过验证的组件，核对适用的悬停、聚焦、按下、禁用和处理中状态。用对比度和可辨识的文字或符号共同表达重要信息。
- 每段界面文案应帮助识别、决定、操作或理解反馈。删减时保留必要的名称、规则、后果和恢复方式。按分组、导航、状态、反馈或品牌表达判断图标、容器、色块和留白的作用，并检查相邻组件的边线、基线、间距是否连贯。
- 需要素材时，先明确它承担的表达，再选择主体、构图、色调、材质和裁切。放进实际页面比较主体与标题、正文和主操作的视线顺序。在目标视口检验裁切、叠字对比和首屏空间，按任务需要决定重排、缩小或省略素材。
- 给重要状态变化设计可理解的反馈。明确动效的触发、变化区域、稳定参照和结束位置。在快速切换、提交及失败重试中检验稳定性，确认系统减少动态效果时仍能识别结果并操作。

## 原型与交接

- 按已确认的范围列出页面、角色、操作路径及适用状态，并映射到可访问的入口。覆盖与任务相关的初始、输入、校验、进行中、成功、空、失败、受限、恢复和边界场景。同一种表现可复用，业务结果和反馈不同的状态应能分别进入。
- 提供可查看的高保真原型。主路径和关键交互应可操作。说明模拟行为、未覆盖状态及尚未验证的条件，把评审入口和演示设置放在产品界面之外或明确隔离。
- 适用的业务和原型确认后，按授权进入实现。沿用项目 UI 规范记录确认范围、原型入口、布局、排版、语义颜色、组件状态和交互规则。未定事项保留为草案。局部调整复用现有约定并按实际影响更新。

## 在实际页面复审

交付预览前，在浏览器打开实际渲染的原型并操作关键路径。交付实现前，从应用正常入口复验受影响的页面。首次设计或整站重做应另做一轮跨页对照。分别检查以下三项。

1. **产品适配。** 用真实感内容检验首屏焦点、信息密度与操作顺序。在相同视口对照有代表性的关联页面，检查角色和任务切换时的连续性。若页面内整齐但跨页气质或核心任务仍不协调，回到构图、密度或素材取舍重新验证。
2. **视觉质量。** 检查构图、字形、字距、行高、对齐、色彩对比、素材工艺、列表节奏和控件细节。用边界数据检查换行、对齐和溢出。在桌面与适用窄屏检查真实渲染，按设计风险补查临界尺寸或不同内容密度。
3. **交互可用性。** 走通适用的正常、错误和恢复路径。检查键盘焦点及可见性、字段报错位置、写入失败后的输入保留、重试和成功后的落点。按内容核对语言标记、控件名称、图像替代文本等语义。存在底部操作、浮层或短时提示时，结合窄屏滚动、长提示和适用的软键盘检查遮挡，并在状态变化进行中观察结果。

记录评审入口、代表性画面、实际操作结果和未验证项。对影响目标的问题在相同条件下复查。模拟原型、真实实现与技术检查各自记录证据。交付时给出预览入口、值得试的操作、确认范围和剩余问题。
