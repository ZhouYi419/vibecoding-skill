# 产品 UI 设计与验收

围绕用户要完成的操作组织页面。用构图、视觉层级、留白、字体和颜色突出主要任务，兼顾清晰反馈和可用性。复用已有设计变量、组件和布局。页面文字应服务于理解、操作或状态反馈，装饰与动效以有实际用途为准。

## 设计依据

- 阅读适用的 `AGENTS.md`、PRD、架构、目标任务卡、现有页面代码和 UI 规范。确认用户入口、主操作、业务边界、数据变化和用户可见状态。沿用已有设计稿和已确认的产品风格。
- 根据请求选择首次设计、局部迭代或验收。用户要求设计或原型时，交付实际可查看的视觉成果。用户要求功能实现时，按当前架构及任务范围交付可运行页面。

## 视觉方向与质量标杆

- 首次设计、视觉重做或用户明确要求提升质感时，先根据产品定位、使用场景、核心操作、信息密度和品牌气质确定构图、排版、素材与动效方向。展示页可以围绕主视觉组织叙事，高频工具页优先让入口容易找到、信息好扫读、操作反馈及时。已有明确风格的局部改动沿用项目规范。
- 以[米哈游产品页](https://www.mihoyo.com/?page=product)作为视觉和交互完成度的标杆。借鉴构图的主次、素材与排版的一致性、响应式细节、切换节奏和反馈的连贯性。根据当前项目选取有价值的手法，按项目自身定位决定视觉表达。有用户指定的参考时，提炼其具体品质，并把它转成当前页面可观察的设计目标。
- 以一张最能体现体验的页面定方向，用接近真实的内容、数据和边界状态验证。方向明确时集中打磨一个方案，方向存在重要分歧时再给少量有实质差异的方案。

## 主视觉与图片

- 先明确图片在页面里的作用，例如建立品牌气质、展示产品细节或帮助用户理解内容。选图或生成前定好主体、构图、光线、色调、文字留白和关键视口的裁切范围。以图片与整个页面的关系决定是否采用。
- 把候选图放进实际版面挑选。检查主体是否清晰且有辨识度，光影、材质和细节是否自然，色调是否与页面协调，标题和主操作是否依然容易找到。若图片只是重复标题含义，或者削弱了页面的视觉重点，可用排版、留白或内容本身建立构图。
- 在桌面和窄屏按实际容器尺寸检查裁切、主体完整度、叠字对比度与首屏空间。发现画面松散、主体被截断或图片和内容脱节时，调整构图或换图再看。主视觉对体验影响较大且方向未定时，可用少量差异明确的候选快速比较。

## 字体与排版

- 按项目气质、阅读场景和信息密度选字体，优先沿用合适的项目字体。新选字体时，用页面实际的中文、拉丁文字和数字试排，确认字形搭配、字重和回退字体合适。
- 分别设计标题、正文、辅助文字和数字的层级。用字号、字重、行高和字距调整阅读节奏，保持标题与正文易于区分，标签和提示易于扫读。金额、日期等需要纵向比较的数字可用等宽数字，并检查单位、小数位和列对齐。
- 涉及排版的任务，在桌面和适用的窄视口检查实际渲染。用长标题、多行正文、真实范围内的大数值和状态提示核对字距、换行、截断、溢出和数字对齐。使用自定义字体时，确认页面实际加载了所选字体，并检查回退时的可读性与布局。

## 按功能逐步设计

项目整体规划时只确定必要的视觉方向和当前选定功能的原型，不提前设计所有页面或虚构未确认的交互。用户确定下一功能并明确必要业务规则后，再设计该功能的页面及相关状态，复用并增量维护已确认的 UI 规范。需求尚未细化时，原型中的业务假设须清晰标注，不能当成确认需求；不因等待后续功能而阻塞当前工作。用户明确要求更大范围的设计时按其要求执行。

## 首次设计与交接

1. 用选定的视觉方向规划页面结构、主次操作和关键视口，确认核心操作在合理的浏览范围内可以直接完成。
2. 制作高保真原型，展示主要路径及影响当前任务的初始、成功、空、错误等状态。交互和动效影响体验时，提供可操作的原型。让动效标识状态变化、保持方向感或确认操作结果，及时反馈，保持操作可用，并提供减少动态效果时的呈现。说明如何打开和查看。
3. 用实际渲染核对构图、比例、信息层级、组件一致性和操作反馈，修正明显问题。向开发交接原型位置、任务及需求 ID、关键视口、布局、排版规则、颜色、间距、组件和状态行为。关键动效注明触发、顺序和结束状态。视觉方案确认后，将可复用规则记入已有 UI 规范，默认路径为 `docs/UI_DESIGN.md`。用于试跑的未确认规则标为草案，说明所采用的设计假设。

## 局部迭代

检查现有规范和受影响页面。优先延续现有信息架构、组件和操作习惯，仅调整与本轮需求相关的区域。发现确需变更的通用规则时，说明影响并同步 UI 规范。

## 实现与验收

1. 使用现有技术栈和设计变量实现授权的任务。沿用适用的任务管理和验收规则。
2. 在环境支持时启动实际页面，在目标桌面与适用的窄视口查看并截图。对照设计检查焦点、层级、字体、对齐、留白、溢出、素材裁切和组件状态。涉及方向变化时，对照本项目的设计目标，判断主操作是否易找，真实内容下的视觉是否仍然成立。
3. 通过真实入口操作主流程和相关失败路径，验证表单提示、状态切换及必要的键盘操作。涉及关键动效时，实际检查其节奏、操作是否及时、减少动态效果时反馈是否清楚。对照任务卡核验结果，修正明显差异后复查。
4. 汇报实际检查的页面、视口、交互和证据。无法实际渲染或执行的检查标记为「待验收」。按实际证据更新任务状态。
